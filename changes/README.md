# Change records

Archive every request under `changes/<change-id>/`.

Standard structure:

```text
changes/CHG-2026-xxxx-<slug>/
  brief.md
  impact.yaml
  execution.yaml
  design.md
  acceptance.md
  tasks/
    <repo-id>.md
  verification/
    result.md
  postmortem.md
```

Notes:

- `brief.md`: Business goals, scope, and success criteria
- `impact.yaml`: Single structured entry point for cross-repository impact analysis
- `execution.yaml`: Machine-readable execution status, owners, write boundaries, worktrees, and locks
- `design.md`: Design decisions and dependency order
- `acceptance.md`: Acceptance checklist for user workflows
- `tasks/`: Repository task cards, generated by default from the repository list in `repos.yaml`
- `verification/result.md`: Verification results, failures, and remaining risks
- `postmortem.md`: Post-release review and knowledge feedback records

The initial scope covers the example product's seven repositories, so each new change record automatically generates these task cards:

- `backend.md`
- `web-portal.md`
- `admin-web.md`
- `mobile-a.md`
- `mobile-b.md`
- `mobile-c.md`
- `miniapp.md`
